# noobenkyo 词库条目

## 命令

```
noobenkyo dictionary guide
noobenkyo dictionary export --completeness no-sentence --keyword 食 --limit 20
noobenkyo dictionary existing words.jsonl
noobenkyo dictionary check words.jsonl
noobenkyo dictionary send words.jsonl
```

- **guide**：打印这份说明。
- **export**：按筛选导出词库里的条目，一行一个，不带进度。参数都可以不写：
  - `--keyword 文字`：包含在写法、词源、读音或释义里。
  - `--completeness`：`word-only`（只有写法）、`reading-only`（写到读音）、`no-sentence`（有释义、没有例句）、`with-sentence`（有例句）。可以写多次；不写表示不限。
  - `--progress`：`any`（不限）、`untouched`（没学过）、`touched`（学过）。
  - `--limit N`：最多导出几行。
- **existing 文件**：文件是条目格式（每行只写 writing，有词源的再写 origin 就够了）。输出其中已经在词库里的单词，每个一行：`第 N 行：写法`，有词源时后面带"（词源：…）"。按 (writing, origin) 精确匹配；不合格式、不会导入的行不列。
- **check 文件**：按导入时的规则检查。通过时没有输出。有问题时每条一行，例如：
  - `第 3 行 明日：丢掉例句 [[明日]]は雨。：目标词里的汉字 明 没有注音`：这条例句不会导入。
  - `第 5 行 ネコ：丢掉语种 日语：没有词源`：语种不会导入。出现这条时，先检查这个词是否违反了"不接受写成片假名的日语词"（见 writing）：ネコ 是日语词，应该写成 猫，也不写语种；真是外来语，就补上 origin。
  - `第 1 行 上：未知字段 gloss`：这个字段会被忽略。

  不合格式的整行（例如写法里有英文、有汉字却没写 kana）不会列出来，导入时直接跳过。
- **send 文件**：送进 app 的导入对话框，用户预览以后才导入。有警告的行也照常送。命令拿不到 app 的回答。送进去的这一份用文件名去掉扩展名当名字（words.jsonl 叫 words），所以要从文件送，不能用 `-`；app 还没取走同名的一份时，命令失败，换个文件名再送。成功时输出"已送进 inbox：名字"。

文件写成 `-` 时读标准输入（send 除外）。退出码：0 是完成；1 是内容有问题，问题打在标准输出；2 是命令没能运行（例如找不到数据），原因打在标准错误。

## 格式

JSON Lines：一行一个 JSON 对象。一行最多对应一个义项；一个词有几个读音、几个义项，就写几行。

| 字段 | 说明 |
|---|---|
| writing | 写法，必填 |
| origin | 词源 |
| origin_language | 语种：词源是哪种语言 |
| kana | 读音 |
| glosses | 释义列表，第一个是主释义 |
| labels | 标签列表 |
| sentences | 例句列表，每条是 `{"marked": "带标记的日语句子", "translation": "中文翻译"}` |

- 下层字段要求上层齐全：有 sentences 就要有 glosses，有 glosses 就要有 kana。没有汉字的单词可以不写 kana。
- stage、passes、lapses、modified_at 是学习进度，写了也会被忽略。
- 不认识的字段会被忽略。

## 各字段的要求

- **writing**：词典形。只能包含汉字和假名，英文、数字、符号（包括 ・）、半角片假名都不行。有汉字就写汉字，有词源的词写片假名。不接受写成片假名的日语词：没有词源的词，有汉字写汉字，没有汉字写平假名，例：ネコ → 猫。写法不同就是不同的单词（分かる / 解る）。
- **origin**：外来语填原词，按原语言的标准拼写，区分大小写，例：コーヒー → koffie。和制外来语和缩略语填组成它的原词，例：パソコン → personal computer。日语固有词和混合词（消しゴム）不写。写法相同、词源不同，就是不同的单词：(コート, coat) 和 (コート, court)。
- **origin_language**：origin 是哪种语言，用中文写，例：koffie → 荷兰语，personal computer → 英语，Arbeit → 德语。没有 origin 就不写。
- **kana**：只能包含平假名和 ー，例：コーヒー → こーひー。
- **glosses**：中文，简洁，第一个是主释义。导入时，义项按释义认：和同一读音下某个已有义项的释义有重合，就并进那个义项；没有重合，就新建一个义项。所以改了已有条目的释义，会多出一个义项。同一个意思在不同读音下各写一行（明日 的 あした 和 あす）。
- **labels**：自由的标签，可以不写。
- **sentences**：每条例句都要：
  - 地道、自然，是母语者日常会说的话。
  - 可以是两个人的对话，写在一行里：甲：「……」　乙：「……」（中间是全角空格）。
  - 语境明确：读完整句，能确定目标词在这里是这个义项的意思。
  - 不能靠句子猜出目标词：把目标词挖空，换成别的几个词，句子也通顺。
  - 同一个义项的几条例句用不同的场景，目标词尽量用不同的活用形。
- **marked**：除了甲、乙，所有汉字都标注音，写成 `{漢字|かな}`。目标词用 `[[ ]]` 标出，必须恰好出现一次，可以是活用形，里面的汉字也要标注音。
- **translation**：通顺的中文，翻译整句或整段对话；对话写成 甲：“……”　乙：“……”。
